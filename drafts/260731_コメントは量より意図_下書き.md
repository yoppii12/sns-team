# 「コメントは量より意図」――Claude Code時代のコードレビュー観、LAplustが仕組みにした理由

先日の定例で、ちょっとした「あるある」が話題になりました。テーマは、AIが書くコードのコメントについてです。

## Claude Codeに書かせると、コメントが増えていく

最近、LAplustの開発現場ではClaude Codeに実装を任せる場面が増えています。効率化には確かに役立っています。

その一方で、あるメンバーがこんな変化に気づきました。「Claude Codeに実装させると、コメントを大量に書いてくるようになった」と。

コードの一行一行に、丁寧すぎるほどの説明が付く。一見、親切に見えます。でも、これは本当に良いことなのでしょうか。

## コメントは「量」では測れない

コードレビューとは、書いたコードを他のメンバーが確認し、品質を担保する工程のことです。そこで読まれるコメントには、本来の役割があります。

コードを読めばわかることを、わざわざ書く必要はありません。むしろ大事なのは、コードだけでは伝わらない「なぜ」です。

なぜこの実装方法を選んだのか。なぜこの条件分岐が必要なのか。そこにこそ、コメントを書く意味があります。

## Masatoの一言：「コメントは量じゃない」

この違和感を、Masatoが定例の場ではっきり言葉にしてくれました。実際の発言はこうです。

「最近Claude Codeに実装させると、コメントを大量に書いてくるようになった。コメントはたくさん書けばいいわけではない。コードを読めば分かることは書かず、なぜそうしているかなど、コードだけでは伝わらない意図を書くべき。それが崩れてきている」

シンプルですが、核心を突いた指摘だと思います。AIが実装を担う場面が増えるほど、この原則を意識的に守る必要が出てきました。

## なぜAIは「分かりきったこと」を書いてしまうのか

Claude Codeのようなコーディングエージェント（AIがコードを自動生成してくれる仕組み）は、基本的に「親切であろう」とします。処理の一つひとつに説明を添えるのは、その表れです。

ただし人間のレビューでほしいのは、動作の説明ではなく、判断の理由です。両者はまったく別のものです。

イメージで比べると、わかりやすいかもしれません。

```
// カウンターを1増やす
counter++;
```

これはコードを読めばわかる説明です。一方で、こういうコメントには価値があります。

```
// リトライの上限に達した場合も処理を止めず、
// 後続のログ集計に影響しないよう例外を握りつぶしている
```

同じ1行のコメントでも、伝えている情報の質がまったく違います。前者はなくても困らず、後者は消えると困る情報です。

## ルールを明文化するだけでは、崩れていく

「コメントには意図を書く」というルール自体は、目新しいものではありません。多くの開発現場で、以前から言われてきたことです。

問題は、AIが大量にコードを生成する時代になり、このルールが徐々に崩れやすくなっている点です。

人が書くコードなら、レビューの中で都度指摘し合えます。しかしAIが書くコード量が増えると、レビューする人間の目が追いつかなくなります。指摘し合う機会そのものが減っていくのです。

## LAplustが選んだのは、「気をつける」ではなく「仕組み化」

そこでLAplustの開発チームは、精神論やルールの再周知だけで終わらせませんでした。

【要相談】コメントの質を自動でチェックし、フィルタリングする専用のAIエージェントを、新たに作る取り組みを始めています。コードを読めば分かる説明的なコメントを検出し、意図が書かれていないコメントには指摘を入れる。そんな仕組みを、社内のツールとして育てようとしています。

この取り組みはまだ開発中で、社外には未発表の内容です。技術文化のアピールとして公開する価値はあると考えていますが、詳細をどこまで開示するかは、この記事を出す前に判断をお願いしたいところです。

## 「動くコード」から「伝わるコード」へ

AIが書くコードの量は、今後も増えていくはずです。だからこそ、人間が担うべき役割ははっきりしてきます。

それは、コードを「動かす」ことではなく、なぜそう動かしているのかを「伝える」ことです。

LAplustでは、AIを使いこなす技術力だけでなく、AIが生んだ新しい課題に気づき、仕組みで解決していく姿勢そのものを、大事にしたいと考えています。開発を依頼する企業の目線に立てば、ここは意外と見えにくい部分だと思うからです。

## まとめ

コメントは量ではなく、意図です。当たり前のようで崩れやすいこの原則を、LAplustではMasatoの一言をきっかけに、仕組みとして守る取り組みに変えました。

AIコーディングが当たり前になった今だからこそ、こうした地味な工夫の積み重ねが、開発チームの本当の実力を作っていくのだと思います。
